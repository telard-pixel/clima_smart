> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish the current adaptive controller as Clima Smart 1.0.1 with reliable daytime-vane retries, accurate documentation, automated checks, and a verified GitHub release.

**Architecture:** Keep the existing controller and standalone regression harness. Move the vane one-shot marker from decision time to the apply boundary, where each requested select can report whether it is complete. Package that narrowly tested fix together with release metadata, README corrections, and one dependency-free GitHub Actions workflow.

**Tech Stack:** Python 3, Home Assistant custom integration APIs, `unittest`, GitHub Actions, GitHub CLI.

## Global Constraints

- Do not change climate thresholds, fan bands, schedules, adaptive-target formulas, defaults, entity identifiers, or live Home Assistant settings.
- Preserve manual vane changes after one successful daytime restoration.
- Do not delete or rewrite existing tags or releases.
- Tag and release `1.0.1` from the exact commit merged into `main`.
- Treat documentation and workflow files as configuration/prose: validate their observable syntax and commands rather than adding source-text tests.

- [ ] **Step 1: Add focused regression coverage**

Add this test beside `test_vanes_go_back_to_the_day_position_once`:

```python
def test_failed_day_vane_restore_is_retried(self):
    ctrl = self._con_alette(posizioni=("swing", "position_0", "position_5"))
    ctrl.entry.options = dict(
        ctrl.entry.options,
        vane_day_horizontal="position_0",
        vane_day_vertical="position_5",
    )
    mattina = GIORNO.replace(hour=8, minute=0)
    tentativi = []

    async def fallisce(domain, service, entity_id, data=None):
        if domain == "select":
            tentativi.append((entity_id, data["option"]))
            # First evaluation: both axes fail. Second evaluation: both succeed.
            return len(tentativi) > 2
        return True

    ctrl._call_target = fallisce
    first = ctrl._compute(mattina)
    asyncio.run(ctrl._apply(first))
    self.assertIsNone(ctrl._vane_restored_on)

    second = ctrl._compute(mattina + timedelta(minutes=5))
    self.assertEqual(second.vane_h, "position_0")
    self.assertEqual(second.vane_v, "position_5")
    asyncio.run(ctrl._apply(second))
    self.assertEqual(len(tentativi), 4)
    self.assertEqual(ctrl._vane_restored_on, mattina.date())

    third = ctrl._compute(mattina + timedelta(minutes=10))
    self.assertIsNone(third.vane_h)
    self.assertIsNone(third.vane_v)
```

This catches the production bug where `_compute()` marks the date before either external service call can succeed.

Add two characterization tests for partial completion as well:

- `test_day_vane_restore_retries_with_one_axis_unconfigured`: leave one axis
  unconfigured while the configured axis fails once and then succeeds;
- `test_day_vane_restore_retries_with_one_axis_already_at_target`: put one axis
  at its target while the other fails once and then succeeds.

In both cases assert that `_vane_restored_on` stays unset after the failure and
is set only after the remaining operation succeeds. These cases cover existing
intended behavior and therefore need not fail before the implementation change.

an entity already at the requested option, or a successful service call. Continue

if wanted is None:
    return True
entity_id = self._cfg(conf_key)
if not entity_id:
    return True
# unavailable / unsupported / refused / stopped -> False
if st.state == wanted:

# preserve the existing command and settle-window bookkeeping

In `_apply()`, capture both results and set the one-shot marker only after all

name: Validate

**Files:**

- Consumes: authenticated Home Assistant REST API and existing live entities/configuration.

- [ ] **Step 1: Confirm authenticated Home Assistant access**

Set `HA_ENDPOINT` to the authorized Home Assistant endpoint and `HA_TOKEN_FILE`
to a regular token file with mode `600`; set both without putting the token
itself in shell history. Prefer HTTPS. If HTTPS is unavailable, use an
authenticated secure tunnel bound to loopback and point `HA_ENDPOINT` at its
loopback endpoint. Direct HTTP is permitted only when the owner explicitly
authorizes the trusted private LAN and neither HTTPS nor a secure tunnel is
available; record that authorization by setting `HA_ALLOW_TRUSTED_LAN_HTTP=1`.

Keep shell tracing disabled while reading the token, pass the authorization
header to `curl` over standard input rather than its argument list, and issue
only the read-only `GET /api/` request:

```bash
test -f "$HA_TOKEN_FILE"
test "$(stat -c '%a' -- "$HA_TOKEN_FILE")" = 600
case "$HA_ENDPOINT" in
  https://*|http://127.0.0.1:*|http://localhost:*) ;;
  http://*) test "${HA_ALLOW_TRUSTED_LAN_HTTP:-0}" = 1 ;;
  *) echo "HA_ENDPOINT must use HTTPS or an explicitly authorized endpoint" >&2; exit 1 ;;
esac
set +x
IFS= read -r HA_TOKEN < "$HA_TOKEN_FILE"
printf 'header = "Authorization: Bearer %s"\n' "$HA_TOKEN" |
  curl --config - --fail --silent --show-error "${HA_ENDPOINT%/}/api/"
unset HA_TOKEN
```

Never print the token, enable tracing around it, persist it in repository files,
or include it in command arguments, URLs, history or logs.

Expected: `{"message":"API running."}`.
